# Nashville Housing API

REST API для анализа данных недвижимости в Нэшвилле, штат Теннесси.

**Технология:** FastAPI

## 📋 Описание проекта

Серверная часть для Практической работы 1, реализованная на фреймворке FastAPI. API предоставляет:
- Доступ к реляционной базе данных SQLite
- Выполнение сложных SQL-запросов с JOIN операциями
- API для машинного обучения (подготовка данных, статистика)
- Скачивание файлов (отчёт, база данных)

## 🚀 Установка и запуск

### Требования

- Python 3.10+
- pip

## 🏛️ База данных

API использует реляционную базу данных SQLite, созданную в Практической работе 1:

**Путь к БД:** `../practice1/nashville_relational.db`

**Структура базы:**
- `parcels` - участки земли (48,559 записей)
- `addresses` - адреса (50,638 записей)
- `properties` - характеристики недвижимости (22,432 записи)
- `owners` - владельцы (19,713 записей)
- `sales` - информация о продажах (56,477 записей)

## 🌐 API Endpoints

### Общая информация

| Метод | Endpoint | Описание |
|--------|-----------|-----------|
| GET | `/` | Главная страница с документацией |
| GET | `/stats` | Статистика базы данных |

### Таблицы данных

| Метод | Endpoint | Описание |
|--------|-----------|-----------|
| GET | `/parcels` | Все участки (с пагинацией и фильтрацией) |
| GET | `/parcels/{parcel_id}` | Участок по ID |
| GET | `/addresses` | Все адреса (с пагинацией) |
| GET | `/properties` | Все характеристики (с пагинацией и фильтром по году) |
| GET | `/owners` | Все владельцы (с пагинацией и фильтром по имени) |
| GET | `/sales` | Все продажи (с пагинацией и фильтром по цене) |
| GET | `/sales/parcel/{parcel_id}` | Продажи конкретного участка |

### Параметры запросов

**Пагинация:**
- `limit` - количество записей (по умолчанию 100, максимум 1000)
- `offset` - смещение (по умолчанию 0)

**Фильтры:**
- `/parcels?land_use=...` - фильтр по типу использования
- `/properties?min_year=...` - фильтр по минимальному году постройки
- `/owners?name_filter=...` - фильтр по имени владельца
- `/sales?min_price=...&max_price=...` - фильтр по цене

### SQL-запросы

| Метод | Endpoint | Описание |
|--------|-----------|-----------|
| GET | `/queries/query1` | JOIN по двум таблицам с сортировкой и агрегацией |
| GET | `/queries/query2` | JOIN по трём таблицам с сортировкой и агрегацией |
| GET | `/queries/query3` | Запрос по одному объекту по всем таблицам |
| GET | `/queries/query4` | Подсчет количества строк по совмещенным данным |

### Машинное обучение

| Метод | Endpoint | Описание |
|--------|-----------|-----------|
| GET | `/ml/data` | Данные для обучения (до 10000 записей) |
| GET | `/ml/stats` | Статистика датасета (корреляции, распределения) |

### Файлы

| Метод | Endpoint | Описание |
|--------|-----------|-----------|
| GET | `/files/report` | Скачать отчёт (report.md) |
| GET | `/files/database` | Скачать базу данных (.db) |

## 📊 Примеры запросов

### Получение статистики БД
```bash
curl http://localhost:8000/stats
```

**Ответ:**
```json
{
  "parcels": 48559,
  "addresses": 50638,
  "properties": 22432,
  "owners": 19713,
  "sales": 56477,
  "total_records": 197819
}
```

### Получение участков с фильтром
```bash
curl "http://localhost:8000/parcels?land_use=SINGLE%20FAMILY&limit=10"
```

### Получение продаж по цене
```bash
curl "http://localhost:8000/sales?min_price=100000&max_price=500000&limit=5"
```

### Выполнение SQL-запроса
```bash
curl http://localhost:8000/queries/query1
```

### Данные для ML
```bash
curl http://localhost:8000/ml/data
```

**Ответ:**
```json
{
  "columns": ["ParcelID", "SalePrice", "LandValue", "BuildingValue", ...],
  "data": [...],
  "count": 10000
}
```

## 🔧 Особенности архитектуры

- **Разделение функционала и отображения:** API не содержит UI, только серверная часть
- **RESTful дизайн:** Следует принципам REST для всех endpoints
- **CORS:** Поддержка кросс-доменных запросов для фронтенда
- **Pydantic модели:** Валидация входных данных
- **Пагинация:** Поддержка пагинации для больших наборов данных
- **Фильтрация:** Встроенные фильтры по ключевым полям
